# ARIS EPC

**ARIS EPC** (Architecture of Integrated Information Systems — Event-driven Process Chain) — это методология и нотация моделирования бизнес-процессов, разработанная компанией **IDS Scheer** (ныне часть **Software AG**) в рамках архитектурной платформы ARIS. EPC представляет процессы как последовательность **событий** и **функций**, что делает её одной из самых распространённых нотаций для описания, анализа и оптимизации бизнес-процессов.

## 🏛 Что такое ARIS

**ARIS (Architecture of Integrated Information Systems)** — это методологическая framework для описания архитектуры предприятия. Она была предложена профессором **Августом-Вильгельмом Шеером** в 1990-х годах и предполагает описание компании в виде нескольких взаимосвязанных представлений (views):

| Представление | Описание |
|---|---|
| **Организационное** | Структура компании, роли, подразделения |
| **Функциональное** | Функции и процессы |
| **Данные** | Информационные объекты и их связи |
| **Выход (Output)** | Результаты процессов |
| **Управление (Control)** | Связующее звено между представлениями |

EPC — это **нотация уровня управления (Control View)**, то есть основной язык описания процессов в ARIS.

---

## 🔗 Что такое EPC

**EPC (Event-driven Process Chain)** — событийная цепочка процессов. Основная идея:

> Процесс — это последовательность чередующихся **событий** и **функций**, где событие запускает функцию, а функция завершается новым событием.

Такая логика позволяет описывать процессы детерминированно и легко проверять их на корректность.

---

## 🧩 Основные элементы нотации

| Элемент | Обозначение | Описание |
|---|---|---|
| **Событие (Event)** | Шестиугольник | Состояние или факт, произошедший в процессе. Не имеет длительности. |
| **Функция (Function)** | Прямоугольник со скруглёнными углами | Действие или задача. Имеет длительность и исполнителя. |
| **Организационная единица (Organizational Unit)** | Овал с вертикальной линией | Роль, отдел или сотрудник, выполняющий функцию. |
| **Информационный объект (Information Object)** | Прямоугольник | Данные, документы, используемые или создаваемые функцией. |
| **Логический оператор (Connector)** | Круг с символом ∧ / ∨ / ⊕ | Управление ветвлением: И, ИЛИ, исключающее ИЛИ. |
| **Поток управления (Control Flow)** | Стрелка | Связь между элементами, задающая порядок. |
| **Процессный интерфейс** | — | Ссылка на другой процесс. |

## 📏 Правила построения EPC

Чтобы модель EPC была корректной, необходимо соблюдать правила:

1. **Чередование**: событие → функция → событие → функция...
2. **Начало и конец**: модель начинается и заканчивается **событием**.
3. **Ветвление**:
   - Каждая развилка должна иметь парную сходилку с тем же типом оператора (кроме XOR).
   - После события не может идти логическое И (только ИЛИ / XOR).
   - Перед событием не может быть логического ИЛИ без предварительного XOR-разделения.
4. **Функция** должна иметь ровно один входящий и один исходящий поток управления.
5. **Событие** не может принимать решения — только фиксировать состояние.

## 🔧 Расширения нотации

- **eEPC (extended EPC)** — расширенная EPC с информационными объектами и организационными единицами.
- **EPC с потоками данных** — добавление входов/выходов данных к функциям.
- **ARIS House** — визуализация всех представлений ARIS.
- **Интеграция с BPMN** — сопоставление элементов EPC и BPMN для миграции моделей.
